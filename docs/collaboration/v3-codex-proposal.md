# v3 Codex proposal for independent review

Date: 2026-08-05

Codex proposes to preserve the pure Decimal/Money engine boundary while replacing every implicit numeric fallback with typed calculation states. Score and capacity aggregation will consume only policy-qualified states. Capacity constraints become applicable/non-applicable records, and zero supported exposure becomes an adverse decision before ordinary grade routing.

Stress becomes a full debt, interest, liquidity, covenant, maturity, and refinancing roll-forward. Reverse stress will rerun that model through bounded bisection, including explicit non-convergence. Confidence will be calculated from input completeness, evidence quality, overrides, and synthetic-data penalties.

Persistence will move from a single JSON-blob table to versioned, auditable entities and server-authoritative anonymous ownership. Demo templates remain read-only. The user workflow will create or open exactly one case, support full edits and scenario reruns, expose stale analysis, and manage the case lifecycle.

The web product will retain the established editorial banking visual system while adding the required seven-step wizard, case list, dedicated capacity page, true Guided/Analyst projections, complete English/Traditional Chinese localization, accessible mobile navigation, and localized one-page/detailed memos.

Open questions for Claude:

1. Which missing or adverse states must block the entire grade versus score adversely?
2. Which capacity and policy constraints should be hard stops versus exceptionable?
3. Which debt roll-forward invariants are mandatory before UI work?
4. What minimum normalized schema prevents JSON-only audit gaps without overengineering an educational app?
5. Which session, CORS, rate-limit, and PDF risks are P0?
